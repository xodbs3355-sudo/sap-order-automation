# 통합 테스트 참고 메모 (2026-08-13 밤 작업분)

주무시는 동안 **GUI ↔ 자동화 파이프라인 통합**을 마쳤습니다. 아침에 테스트하실 때
참고할 내용을 정리합니다. (코드 근거·대기 중인 입력값·질문 답변 포함)

---

## 1. 오늘 통합으로 바뀐 것 (요약)

| 구분 | 내용 |
|---|---|
| GUI 예시 제거 | 좌측 표·우측 실행대상/단계 카드·처리 로그의 **하드코딩 예시를 전부 삭제**. 시작 시 전부 빈 상태(실가동). |
| ▶ 선택 건 실행 | 이제 실제로 동작. 체크한 행의 입력값을 모아 → 코드로 변환 → 6단계 파이프라인 실행 → 우측 패널·로그 실시간 갱신. |
| 지역 코드 | 구간명(주소)에서 시/군·동을 뽑아 코드로 변환하는 **코드표(B안)** 채택. `sap/region.py` + config `지역`. |
| 접수 방식 | 다건 안전성을 위해 **행 번호 → 구간코드(CMP) 기준**으로 변경(`zrec0002.receive_by_cmp`). |
| 상세 로깅 | `applog.py` 신설. **파일(logs/app_날짜.log) + 화면 로그**에 단계·입력값·상태바·예외 트레이스백까지 기록. |

## 2. 질문 답변 — 지역 코드 선택 기반 & 행정동/법정동 중복

### Q1. 지역코드를 선택하는 기반이 무엇인지? 결국 공사명(구간명)에 국한되는 게 맞나?
**네, 맞습니다.** 화면에 시/군·동을 따로 입력받지 않고, **구간명(주소 문자열)** 하나에서
시/군과 동/리를 뽑아 코드로 바꿉니다.
예: `"춘천시 동면 만천리 844-11번지 인입공급관"`
- `춘천시` → 구/군 코드
- `동면 만천리` → 동 코드

> 그래서 구간명이 정확해야 변환이 됩니다. 못 뽑으면 그 건은 **자동을 멈추고 "수동 처리"로
> 로그**에 남깁니다(엉뚱한 코드로 발주하지 않도록).

### Q2. 행정동/법정동에 따라 지역명이 중복되는데 어떻게 해소하나?
표에 `동/읍/면` 컬럼엔 **행정동**(예: 조운동)이, `읍면동` 컬럼엔 **법정동**(예: 운교동)이
옵니다. 같은 `조운동`이 `운교동(11000)`·`조양동(10800)` 두 줄로 갈려서, 행정동 이름만으론
코드를 하나로 못 정합니다.

**해소 방법 — 매칭 키를 "법정 기준"으로 잡습니다:**
- **동 지역**(도시): 키 = **법정동**(운교동·소양로3가…). 주소엔 법정동이 쓰이므로 딱 맞음.
- **면/읍 지역**: 키 = **"면 + 리" 전체**(동면 만천리). 리까지 있어 유일함.

즉 주소에 실제로 쓰이는 **법정 지명**으로 대조하므로 `조운동` 같은 행정동 중복이 사라집니다.
그래도 코드가 갈리는 애매한 경우엔 **"중복"으로 판단하고 수동 처리**로 넘깁니다(추측 발주 방지).

동작 확인:
```
python -m sap.region      # 샘플 구간명 몇 개를 시험 변환해 봅니다
```

## 3. ⚠️ 아직 채워야 할 입력값 (테스트 전 확인)

| 항목 | 현재 상태 | 필요 조치 |
|---|---|---|
| **동 코드표(전체)** | 춘천 **34행만** 이미지 전사 시드(검증 필요), 홍천 **0행** | 엑셀 주시면 `tools/import_region_excel.py`로 **한 번에** 채웁니다(오타 0). |
| **홍천군 구/군 코드** | `""`(미확인) | SAP ZREC0100 구/군 F4 에서 홍천군 코드 확인 → config `지역.구군코드.홍천군`. |
| **춘천시 구/군 코드** | `51110` (테스트에서 쓴 값) | 실제 값이 맞는지 확인. |
| **구간명 실제 형식** | 샘플 1개만 확보 | ZREC0002 목록의 **구간명 2~3개**를 보여주시면 파서를 최종 점검합니다. |

> 위가 채워지기 전엔, 해당 지역 건은 "지역 코드 확정 실패(수동)"로 로그에 남고 건너뜁니다.
> 프로그램이 멈추거나 잘못 발주하진 않습니다.

### 엑셀로 코드표 채우는 법 (아주 간단)
1. SAP F4 목록을 엑셀(또는 CSV)로 저장. 열 제목에 `구/군, 동/읍/면, 읍면동, 순번` 포함되게.
2. 터미널에서:
   ```
   python tools/import_region_excel.py  지역코드.xlsx
   ```
   (엑셀은 `pip install openpyxl` 필요. 안 되면 CSV 로 저장해 넣으세요.)
3. 실행하면 `settings.json` 백업(`.bak`) 후 `지역.동목록`을 채웁니다.
4. `python -m sap.region` 으로 몇 개 변환 확인.

## 4. 실행 흐름 (선택 건 실행 시 내부 동작)

체크한 행마다:
1. **입력 → 코드 변환**
   - 굴착허가 대상/비대상 → `1`/`2`
   - 허가청/시공업체 **이름 → 코드** (config)
   - 구간명 → **시/군·동 코드** (`sap/region.py`)
   - **승인투자비 → 도로재질·연장·PLP** (`config_manager.lookup_price_smart`, 연도 자동 판별)
   - 하나라도 실패 → 그 건 "준비 실패(수동)"로 로그, 건너뜀.
2. **6단계 파이프라인** 실행: ZREC0002 접수(CMP 기준) → ZREC0100 → ZMEC0210 → ZREC2030 → ZREC2040 → ZREC0208
3. 단계마다 우측 **단계 카드/진행바/실행대상 목록**과 **로그**를 실시간 갱신.
4. 한 건 실패해도 **다음 건은 계속** 진행.

`TSRM 전송 건너뜀` 체크박스 + `test_server_mode=true` 면 마지막 TSRM 발송은 생략합니다(안전).

## 5. 로그 확인

- **파일**: `logs/app_YYYYMMDD.log` (프로그램 껐다 켜도 남음). git 에는 안 올라갑니다(`.gitignore`).
- **화면**: 우측 하단 `로그` 버튼 → 처리 로그 창(실시간).
- 오류가 나면 파일 로그에 **전체 트레이스백**이 남으니, 그 부분을 보여주시면 원인을 정확히 잡습니다.

## 6. 단독 테스트 스크립트 (기존)

| 스크립트 | 용도 |
|---|---|
| `python -m sap.region` | 구간명 → 코드 변환만 시험(SAP 불필요) |
| `python config_manager.py` | 설정·단가표 자가진단(SAP 불필요) |
| `python test_pipeline.py` | 한 건 6단계 전체(SAP 필요, 상단 WORK 값 수정) |
| `python test_zrec0208.py` | 발주서 단계만(SAP 필요) |

> `test_pipeline.py` 의 `WORK["row"]` 는 이제 **사용 안 함**(접수는 CMP 기준). `cmp` 값만 맞으면 됩니다.
